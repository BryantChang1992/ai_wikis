## 核心架构：三层约定

Fluss 客户端写入流程遵循明确的三层约定：

### Layer 1: Connection（重量级全局单例）

`ConnectionFactory` → `Connection`：
- 全局唯一实例，管理到 Fluss 集群的长连接
- 持有 RPC 客户端、配置信息、schema registry 等
- 生命周期与应用进程一致

### Layer 2: Table（轻量级 per-thread）

`Connection` → `Table`：
- 每个线程独立持有 Table 实例
- 表级别配置、schema 绑定
- 轻量创建，无状态依赖

### Layer 3: AppendWriter（异步 flush）

`Table` → `AppendWriter`：
- 本地缓冲写入，异步批量 flush 到服务端
- 支持自动 batch、重试、背压

## 全链路流程

```
Client Application
  │
  └─ ConnectionFactory.create(url, config)
       └─ Connection (全局单例)
            │
            ├──────────────────────────────┐
            │                              │
       MetadataUpdater                WriterClient
       (后台拉取 schema/           (管理多 bucket 路由
        bucket/format)               + 重试 + 背压)
                                          │
                                    ┌─────┼─────┐
                                   Bucket0 Bucket1 BucketN
                                          │
                                    AppendWriter
                                    (本地缓冲 → 异步 flush → RpcClient)
```

## 关键组件详解

### MetadataUpdater

后台守护线程，定期从 Fluss Coordinator 拉取：
- 最新 table schema
- Bucket 分配信息
- 数据格式（Arrow/Row）
- 在 schema 变更时自动重新绑定

### WriterClient

管理多 bucket 路由的核心：
- 根据 partition key 计算目标 bucket
- 维护每个 bucket 的 AppendWriter 实例
- 处理重试逻辑（服务端 overload、网络超时）
- 背压信号从服务端传递到客户端

### AppendWriter

单 bucket 的写入缓冲器：
- 本地内存缓冲区
- 达到 batch size 或 timeout 时异步 flush
- flush 通过 RpcClient 发送到 Fluss Server
- 返回 ack 后才标记写入完成

### RpcClient

底层 RPC 通信层：
- 基于 Fluss 自定义 RPC 协议
- 连接复用、请求队列、超时控制

## 与 Flink/Spark 集成

Flink 的 Fluss sink connector 通过 `fluss-flink-common/sink/writer` 封装了相同的三层约定，将 Flink 的 checkpoint 机制与 Fluss 的 flush 流程对齐。

## 架构亮点

1. **三层分离**：重量级连接 / 轻量表 / 异步写入器，职责清晰
2. **Metadata 后台驱动**：schema/bucket/format 变更不影响写入路径
3. **多 bucket 路由**：WriterClient 的 bucket-aware 设计支持弹性扩缩
4. **异步 flush + 背压**：append-only 模型下缓冲和重试自然匹配
