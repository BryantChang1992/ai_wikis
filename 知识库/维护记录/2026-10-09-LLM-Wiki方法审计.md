# LLM Wiki 维护方法审计与修正

审计日期：2026-10-09。基线：`BryantChang1992/ai_wikis@31556789a70fecf2c2cd950e02084b38db7ce07d`。结论：已有 sources / wiki / schema、索引、日志与综述的基础，但运行规范混入第三方扩展，且存在规则相互矛盾、来源索引滞后和关联更新缺口。此次修正运行方法，并实际补齐近期卡片的综合联系；不以换目录名代替维护。

## 改前与改后

| 检查项 | 基线发现 | 本轮实际处理 |
|---|---|---|
| 方法归属 | 社区 v2 被写成作者方法的升级，confidence 强制值与禁止机械衰减修订并存 | 重写 schema，明确作者模式与本库工程约定；旧分值和图谱兼容保留，不再强制或机械衰减 |
| 规则入口 | 只有深层维护说明，且包含不存在的脚本与模板 | 添加根 AGENTS.md；将维护流程指向真实 Python 检查器及测试 |
| 原件与分析 | sources README 把所有文件叫只读原件，web 实际主要是分析稿 | 区分原件不可改写、派生分析可纠错；记录 sources/papers 下 18 个 PDF Git 对象基线，LSM-Raft 继续标记无效下载 |
| 来源索引 | Howard 条目重复、虚列未跟踪 PDF、混用另一论文编号；HATS 描述残留旧错配 | 按当前已存在的精读纠正索引，未重新声称核读 PDF |
| 查询沉淀 | 缺明确的 query → 证据回答 → 可复用回写流程 | 加入索引导航、证据分层、范围内回写与知识缺口登记 |
| 摄取后的综合 | 八张近期卡片中七张没有其他 wiki 页的入链 | 增加 [[知识库/wiki/synthesis/异步存储任务的安全边界|异步存储安全边界综述]]，按代际、重试、恢复进度连接八张卡并补双向引用 |
| 矛盾与缺口 | 若干规则要求删断链/自动 supersede，未解问题散落清单 | 增加 [[知识库/维护记录/待核验与知识缺口|统一缺口表]]；按版本和条件判断，不能以新旧或分数自动判胜 |
| 发布边界 | 仓库说明写 private，GitHub 实际 visibility=public | 纠正“未发布博客不等于私密”；禁止新增未授权私人内容，不更改仓库权限 |
| 提交与同步 | git add -A、盲目 pull 与保护用户修改规则冲突 | 明确按路径提交、检查分歧、禁止强制覆盖，新增桌面同步判定流程 |

## 验证范围与结果

基线完整目录树含 623 个文件（695 个树条目），内容审阅与机器解析覆盖知识库 Markdown 及维护入口；二进制原件依据完整 Git 树做存在性/对象核对，未在本轮逐篇下载重读。

- 基线 130 个 wiki Markdown：116 张直接页面、11 篇领域综述、3 份历史维护/方案页；全部可从知识库 README 到达。
- 基线未发现实质性的缺失/歧义知识链接或缺失的本地 sources 引用。文档中的未转义 wikilink 语法示例单独归类，不伪报为技术知识断链。
- 新增一篇实质性综述后为 131 个 wiki 页面；八张近期机制卡均有来自综述的入链，并可反向到达综述。三份历史维护页无技术页入链属于合理角色，不为消除统计而加关系。
- 检查器覆盖路径、重复顶层 frontmatter key、基本 sources、索引可达性和重复标题线索；不校验外部 URL 可达性、章节锚点、完整 YAML 语义、论文事实或 Mermaid 渲染。
- 保留具体警告：四个嵌套 source_citations 超出轻量解析器范围；事务模型页缺 sources 字段但需另审正文证据；Fluss 同标题卡与综述重叠，Doris/InfluxDB 调研与综述仅标题有别，保留兼容路径与后续双端合并事项；历史语法示例保留。
- 所有原始 PDF、已有博客映射正文、232 条同步映射及原有实体缓存均保持原样。本轮新综述只在 vault，不自动发布博客；未用清单哈希掩盖未同步正文。

本轮实际执行 17 项检查器单元测试，全部通过；工作快照的结构检查退出码为 0。机器结果摘要见 [[知识库/维护记录/2026-10-09-结构核验.json]]，保留基线例子误报与解析覆盖边界，避免把“零结构错误”解释成“全库无问题”。

## 未完成与边界

这不是对全库技术事实的重新背书；旧卡状态、created 和 source_checked 不因本轮 lint 自动升级。LSM-Raft 原文取得、15 个 pending_concepts 的选题、历史评分证据和重复角色演进继续在缺口表中。

本次远端修正与用户桌面 Obsidian 的实际拉取是两项验证。桌面 HEAD、工作区和当前打开 vault 尚需在授权的用户电脑上独立核对；云端快照不能证明桌面同步。

## 复跑

在完整 checkout 根目录运行：

```sh
python3 -m unittest discover -s scripts -p 'test_lint_wiki.py'
python3 scripts/lint_wiki.py
```

仅取得文本快照时，可为检查器提供可信的完整 GitHub recursive tree：`--inventory <tree.json>`。该模式只补路径存在性，报告中会说明未读取的 Markdown 数量，不能等同全仓内容审阅。
