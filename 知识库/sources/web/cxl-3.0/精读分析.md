## 背景

CXL（Compute Express Link）是一种开放标准的 CPU-to-device 互连协议，建立在 PCIe 物理层之上。CXL 3.0 基于 PCIe 6.0 物理层，预计 2026 年产品化。

## CXL 演进

| 版本 | PCIe 基础 | 关键特性 |
|------|----------|----------|
| CXL 1.1 | PCIe 5.0 | Type 1-3 设备（Cache/Memory），点对点 |
| CXL 2.0 | PCIe 5.0 | 内存池化（pooling）、switching、multi-host |
| CXL 3.0 | PCIe 6.0 | 全局内存共享、多级 switching、PBR 协议 |

## CXL 3.0 核心能力

### 1. 弹性内存池（Elastic Memory Pooling）

- 多台服务器共享一个 CXL 内存池
- 按需动态分配/释放 CXL 内存
- 完全内存容量利用率（overcommit 支持）

### 2. 全局共享内存（Global Shared Memory）

- 多主机共享同一 CXL 内存区域
- 硬件级 cache coherence（CXL.cache 协议）
- 延迟在数百 ns 级别（相对 RDMA 的 μs 级有很大优势）

### 3. CXL Fabric 管理

- Fabric Manager 管理 CXL 拓扑
- Multi-Level Switching（MLS）支持跨机架内存共享
- PBR（Port-Based Routing）替代 PCIe 树形拓扑

## 对数据库系统的潜在影响

### 场景 1：内存数据库从 Scale-out 到 Scale-up

传统内存数据库（Redis/VoltDB）受限于单机内存 + 网络分片。CXL 3.0 提供以下可能：

- 单节点可访问 TB 级 CXL 内存池
- 消除分片带来的跨节点事务开销
- 内存弹性扩容（从 256GB → 2TB 无需重启）

### 场景 2：LSM-tree 的 CXL 加速

- CXL 内存作为 LSM-tree 的扩展 buffer pool
- Block cache 可溢出到 CXL 内存（延迟可控，仅 2-3x 本地内存延迟）
- Compaction 中间结果使用 CXL 内存避免写盘

### 场景 3：存算分离的"近存储"缓存

- CXL 内存附着在存储节点上，作为近存储缓存层
- TiDB/TiFlash、Aurora Limitless 等存算分离架构可将热数据缓存在 CXL 内存中
- 避免网络往返存储层

### EDBT 2026 论文

EDBT 2026 已有论文探讨动态 CXL 内存池分配策略，关注：
- 多租户环境下的 CXL 内存分配 fairness
- CXL 内存的分配粒度（4KB page → 128MB segment）
- CXL 内存故障的容错机制

## 挑战与不确定性

1. **硬件生态进展**：Intel Sapphire Rapids EMIB、AMD Genoa 对 CXL 的支持程度不一
2. **软件栈**：CXL 内存的 OS 集成（DAX vs NUMA）、DBMS buffer manager 适配仍需时间
3. **成本**：CXL 交换机 + CXL 内存模块的 TCO 尚未验证
4. **延迟**：CXL 内存 vs 本地 DDR5 有 2-3x 延迟差异，对延迟敏感型工作负载的影响需评估
