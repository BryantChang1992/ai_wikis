# 知识重要性与生命周期管理

本规则是此库的工程实现，不是 Karpathy 原文规定的评分算法。目标是让重要内容更容易找到，让过时或重复入口可追溯退出，同时保留来源与历史。

## 三件事分别管理

- **重要性**：在当前研究中是否相关、是否被实际复用、是否连接不同主题。影响 [[知识库/阅读优先级|主阅读入口]] 的展示顺序。
- **可信度**：断言的原始证据、独立来源、版本条件与核验范围。由正文及 source_checked/status 等证据记录表达；脚本不改 confidence，也不把引用多当作更正确。
- **生命周期**：active 为主入口；reference 为保留参考入口；superseded 为有明确替代的旧页；merged 表示经过审阅的规范入口合并。状态存于事件投影，不批量改原文 frontmatter。merged 不代表脚本删除或拼接正文，需另有内容审阅。

## 输入与真实可观测信号

配置、追加事件和执行记录位于 `维护记录/动态管理/`。本轮只将 `wiki/` 的非 meta 知识页纳入排序，原始来源不参与淘汰。

1. 研究相关性来自 config 的 research_tags。初始标签对应 [[知识库/purpose|既有研究目标]] 中的分布式系统、数据平台和 AI 基础设施；不是依据私人阅读行为推测。变更研究目标需实际调整配置，并运行维护生成可审阅差异。
2. 可观测复用记录只接受公开仓库内真实产物：必须有文件、SHA256 和指向该知识页的明确链接。使用 record-use 时说明实际复用理由，不把“看过”“浏览过”臆造为使用。
3. 同一知识页在同一公开产物的多个修订、多个链接只算一份复用；完全相同内容的镜像副本也去重。没有有效记录时是“已记录公开复用 0”，不能解释成用户从没用过。没有访问次数埋点。
4. 跨主题引用由其他非 meta 知识页的真实链接推导。每个来源按配置中的第一个匹配主题归类；同一主题、规范入口及其重复别名去重。README、日志、生成入口不参与，避免排序结果给自己加权。
5. 历史证据发生变化时保留事件，并产生待复核候选；失效复用证据不计入当前自动优先级。旧决定仍有记录与待审标识，不因文件变化悄悄删除历史。

排序使用可解释的顺序：研究相关性优先，然后有效公开复用产物数，再按独立入链主题数，最后用路径稳定打破同分。没有综合“真理分数”、时间衰减、访问热度或学习到的隐式权重。

## 自动执行与审阅边界

每次调用维护命令时，程序自动重建主阅读排序和候选清单，并在结果变化时追加执行记录。相同输入重复执行应无变化；不创建后台任务，也不意味着 GitHub 会自行定时运行。

自动化允许做：计算上述信号、调整生成入口中的顺序、列出重复内容/证据变化的候选、根据已明确登记的生命周期决定生成主入口与参考入口。

以下必须先完成证据审阅，再显式记录 decision：移出主入口、标为被替代、确立合并目标。原件、原页面正文、用户修改及稳定链接不由脚本删除、搬移或重写。长期未用只可由维护者提出复核，当前不采集阅读时间也不运行闲置计时器。

相互矛盾的页面不能只按发布时间或引用数量判胜。比较版本、假设与来源；无定论保持并列，进入 [[知识库/维护记录/待核验与知识缺口]]。

## 可执行工作流

先读本库 schema，并检查输入证据。仓库根目录的命令：

```sh
# 只读预览当前排序与候选
python3 scripts/manage_wiki.py --root . plan

# 结构预检 → 重建生成入口/追加执行日志 → 结构复检
python3 scripts/maintain_wiki.py --root .

# 只读验证；生成物过期则返回非零
python3 scripts/maintain_wiki.py --root . --check

# 完整测试
python3 -m unittest discover -s scripts -p 'test_*.py'
```

若首次初始化或生成文件被误删导致预检只报这些生成目标缺失，可先运行 `python3 scripts/manage_wiki.py --root . apply` 重建，再运行维护入口及 `--check`。这只恢复命名的生成文件，不用于绕过真实知识页断链或来源错误；本次提交已包含首次生成结果。

在真实完成一次公开产物复用之后登记，不能只为提升排名而填记录：

```sh
python3 scripts/manage_wiki.py --root . record-use <知识页路径> --evidence <公开产物路径> --reason <本次实际复用的中性说明>
```

路径、哈希和可追溯关系由程序校验；语义上是否真正复用仍由操作者核实。只写公开技术产物路径与中性原因，不保存私人聊天、个人阅读轨迹、账号或私有项目内容。

审阅后退出主要入口、恢复旧决定的例子：

```sh
python3 scripts/manage_wiki.py --root . decision <旧知识页> reference --replacement <规范知识页> --evidence <公开审查记录> --reason <证据与理由>
python3 scripts/manage_wiki.py --root . restore <事件ID> --evidence <公开审查记录> --reason <恢复理由>
python3 scripts/maintain_wiki.py --root .
```

restore 追加反转事件，不删除旧事件；可以恢复生命周期或撤销误记复用。任何恢复都须复跑生成与检查，按正常 Git 流程提交，不能改写历史假装从未发生。

## 文件与输出

- config.json：研究标签、主题分组及检查范围；不放置信度权重。
- events.jsonl：复用、生命周期决定和恢复事件，追加保存。
- priority.json：当前排序、信号、有效状态及理由，可从事件和当前知识页重建。
- candidates.json：待审重复、证据变化等候选，不能因为生成候选就宣称已经合并。
- execution.jsonl：实际重建发生变化时的执行摘要，记录升降/退出/恢复所依据的输入和变化。
- [[知识库/阅读优先级]]：供人和 Agent 使用的主入口；完整旧目录仍在 [[知识库/README]]，稳定路径不丢。
