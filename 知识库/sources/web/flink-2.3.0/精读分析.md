## 版本概览

Flink 2.3.0 实现完整或核心功能的 **15 个 FLIP**，关键突破集中在 SQL 层和存储层的现代化。

## 关键特性深度分析

### 1. FROM_CHANGELOG / TO_CHANGELOG — SQL 层 Changelog 双向转换

Flink 2.3 在 SQL 层面首次实现了 append-only ↔ changelog 的双向转换：

- **FROM_CHANGELOG**：将带操作列的 append-only 流转为动态表（支持自定义 CDC 格式映射）
- **TO_CHANGELOG**：将动态表物化回 append-only changelog 流——这是 Flink SQL 首次能在 SQL 层面将 retract/upsert → append-only

**工程意义**：
- 消除了从 DataStream API 到 SQL 的功能迁移鸿沟
- TO_CHANGELOG 支持归档、审计、写入 append-only sink
- 未来版本将扩展 PARTITION BY、invalid_op_handling、produces_full_deletes

参考：FLIP-564

### 2. Materialized Table DDL/ALTER — 物化表一等公民化

Flink 2.3 为物化表带来完整 DDL 能力：

- CREATE MATERIALIZED TABLE 支持显式列定义（含 watermark/PK）
- ALTER MATERIALIZED TABLE：ADD/MODIFY/DROP/RENAME
- START_MODE 子句：精确控制 refresh 起始位置，避免不必要的历史数据重处理

**关键突破**：之前物化表是"二等公民"——改 query 需要 drop & recreate。现在 DDL 层面支持演化，消除了运维痛点。

参考：FLIP-550, FLIP-557

### 3. SinkUpsertMaterializer 重构 — 显式冲突处理

当 upsert key ≠ primary key 时（多阶段转换/投影/Join），旧版本 SinkUpsertMaterializer 存在无界状态增长问题。

2.3 引入 ON CONFLICT 子句：
- `DO NOTHING` — 静默跳过冲突
- `DO ERROR` — 冲突时失败
- `DO DEDUPLICATE` — 物化并去重（旧行为，但需要显式声明）

配合 watermark-based compaction 减少状态大小。

参考：FLIP-558

### 4. Native S3 FileSystem（Experimental）

全新 S3 文件系统 `flink-s3-fs-native`，基于 AWS SDK v2，完全脱离 Hadoop/Presto 依赖：

- 异步 I/O、零 Hadoop 依赖、统一的 FileSystem + RecoverableWriter
- IRSA（IAM Roles for Service Accounts）原生支持
- 独立配置命名空间 `s3.*`（而非 `fs.s3a.*`）

参考：FLIP-555

### 5. Adaptive Partition Selection — 自适应分区

基于下游 task 负载动态选择数据分区目标，优化背压处理。对 RebalancePartitioner 和 RescalePartitioner 生效。

参考：FLIP-339

### 6. Watermark Alignment 改进

引入 watermark alignment buffer（默认 3），解决之前的对齐延迟问题。在 2.2 版本中，watermark alignment 实际将积压处理速度限制在 drift/update_interval（如 30s/s），2.3 通过 buffering 消除了此瓶颈。

参考：FLINK-37399

## 补丁版本：Flink 2.1.3

同周期发布，包含 5 个 bug 修复（来自 Flink 2.1.x 主线）。

## 关键 Bug 修复：MiniBatch Aggregation Record Loss

修复了 MiniBatchGroupAggFunction 中当某 key 的 minibatch 仅含 retractions 且无现有状态时，函数错误提前返回导致丢失其余 key 的问题（FLINK-35661）。
