# 仓库分工说明

## 概述

CHANG_AI_TEAM 维护两个 Git 仓库，分别服务于知识组织和站点发布。2026-10-09 核验 `ai_wikis` 的 GitHub visibility 为 public；“未同步博客”不等于私密。

## 仓库清单

| 项目 | 仓库名 | 用途 | 访问方式 |
|------|--------|------|----------|
| Obsidian Vault | `ai_wikis` | 公开技术知识库 | Obsidian 客户端 + GitHub |
| 博客/站点 | `ai_memory_chang_ai_team` | 对外技术博客 & 设计文档 | GitHub Pages |

## 1. ai_wikis（Obsidian Vault）

- **远程**: `git@github.com:BryantChang1992/ai_wikis.git`
- **本地路径**: `work/ai_wikis/`
- **用途**: 公开技术知识库，用 Obsidian 打开管理
- **特点**: 当前为 public repo，只可写入获准公开的内容；私人会议记录、OKR、凭据与未授权内部草稿不得写入。历史“私有 repo”描述已失效。

### 目录结构

```
ai_wikis/
├── 团队规范/       ← 团队流程、角色定义、基础设施文档
├── 技术文章/       ← 技术分析、调研
├── 知识库/         ← 技术知识点沉淀
└── 项目文档/       ← 各项目设计文档
    └── agent基础设施可观测性平台/
```

## 工作流程

1. **获准公开的技术材料** → 在 `ai_wikis` 中组织与维护；内部文档使用另外获准的私密位置
2. **站点发布** → 只在本次发布授权范围内同步到 `ai_memory_chang_ai_team`；仅入 vault 的专题不自动发布到博客

## Git 操作规范

> [!warning] 强制遵守
> 先核对真实路径、分支、远端与未提交修改，再 fetch 并检查 ahead/behind。只提交本次明确文件；不自动 `git add -A`、reset --hard 或强推。分歧和重叠修改先保留并合并，推送后读回远端。桌面是否同步单独验证，见 [[知识库/维护记录/Obsidian与GitHub同步操作]]。
