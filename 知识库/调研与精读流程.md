# 调研与论文精读双端沉淀流程

当前维护总规则见 [[知识库/schema]]；查询回写、综述关联更新与缺口登记同样适用于此流程。

## 普通调研

- 已发布完整报告存入 `技术文章/博客同步/`，保留公开 URL、源路径、源 commit、观察窗口与同步日期。项目讨论、评审、主干合并、候选版本与正式发行分别记录。
- 顶会论文与技术博客使用可验证的一手资料；论文/网页的来源及阅读材料放入 `知识库/sources/papers/` 或 `sources/web/`。已有相同论文、URL 或机制优先合并补充，保留用户修改与 Git 历史。
- `知识库/wiki/` 的卡片围绕稳定问题组织，包含问题、机制、取舍、适用边界、来源与日期。报告是完整证据上下文，卡片只保留可复用知识，二者不算独立证据。
- 更新总索引、来源索引和有意义的相关双链；实体图谱作为可选派生缓存，更新时注明实际范围。相同期号只保留规范版本，旧 URL/别名指向同一报告。

## 用户指定论文精读

1. 核对标题、作者、年份、会议、版本与实际原文。只有原文可访问且允许保存/再分发时才将 PDF 放入公开 vault；否则保留出版社、会议、arXiv 或作者的原文链接，并明确缺口。网页可公开访问不自动代表允许转载 PDF。
2. 在该论文目录写详细阅读笔记：问题与假设、关键机制与不变量、可走通示例、章节/图表定位、实验配置/指标/基线、局限、作者结论与工程推论。未报告或未复现的项目直接注明。
3. 提炼少量知识卡，链接原文、详细笔记和既有相关卡片；不把周报提及自动标成已经完整精读。
4. 仅在明确要求时全文翻译，先核验原文取得情况、版权/许可和公开发布权限；全文、节译、译述明确区分，不能用摘要代替全文。无法合法公开的 PDF 或译文不推送至这两个公开仓库。
5. 同时更新公开 GitPage 与 Obsidian 的适合公开内容、原文链接和阅读笔记；内部信息不进入公开发布链路。已有公开报告无需为同步而重发，新卡是否单独发布按当次范围处理。

## 校验与冲突处理

- 先读两边完整文件和同步清单，双方同时变化时合并而不盲目覆盖；正文确实对齐后才更新摘要值。
- 运行增量 Markdown/frontmatter、来源、附件及 Obsidian 双链检查；涉及博客正文或导航时运行相应构建/页面检查。
- 两份同步清单保持一致。提交后读取远端 commit 和文件；桌面 Obsidian 是否已拉取要单独验证，仓库推送成功不代表桌面已同步。
